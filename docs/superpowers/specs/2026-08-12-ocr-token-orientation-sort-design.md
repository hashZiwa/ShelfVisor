# OCR Token Orientation-Aware Sort Design

## Goal

각 OCR 이미지에 매핑된 토큰 박스의 평균 형태를 이용해 텍스트 읽기 방향을
판단하고, 그 방향에 맞게 토큰을 정렬한다. 원본 방향과 90도 반시계 회전
방향은 서로 독립적으로 판단한다.

## Current Behavior

현재 모든 OCR 토큰은 박스의 좌상단 좌표를 기준으로 `(y, x)` 순서로
정렬된다. 따라서 토큰 박스가 세로로 길고 텍스트가 왼쪽에서 오른쪽으로
배치된 이미지에서도 위쪽 좌표가 우선되어 잘못된 순서가 만들어질 수 있다.

## Sort Rules

각 방향 이미지의 토큰 목록에 대해 다음 규칙을 적용한다.

1. 모든 토큰 박스의 폭 평균과 높이 평균을 계산한다.
2. 평균 폭이 평균 높이보다 크거나 같으면 가로형 토큰으로 판단한다.
3. 가로형 토큰은 위에서 아래로 `(y, x)` 순서로 정렬한다.
4. 평균 폭이 평균 높이보다 작으면 세로형 토큰으로 판단한다.
5. 세로형 토큰은 왼쪽에서 오른쪽으로 `(x, y)` 순서로 정렬한다.

평균 폭과 평균 높이가 같은 경우에는 사용자 결정에 따라 위에서 아래로
읽는다. 주 정렬 좌표가 같은 토큰에는 나머지 좌표를 보조 키로 사용해
결과가 항상 결정적이도록 한다.

## Architecture

`app/analysis/ocr/ocr_processing.py`에 토큰 목록을 받아 정렬 키 또는 정렬된
목록을 제공하는 작은 순수 헬퍼를 추가한다. `map_ocr_result_to_rows`는 각
`variantResults`에 토큰 매핑을 마친 뒤 이 헬퍼를 사용한다.

기존 OCR 응답 형식과 결과 행 구조에는 필드를 추가하지 않는다. 정렬 후
토큰 목록을 사용해 방향별 `text`를 조합하므로 선택된 방향의 최종 텍스트도
새 읽기 순서를 따른다. 디버그 confidence 목록은 같은 토큰 목록을 사용하므로
`box1`, `box2` 번호 역시 새 정렬 순서를 자동으로 반영한다.

## Data Flow

1. OCR annotation을 현재 방식대로 해당 행과 방향 이미지에 매핑한다.
2. 방향 이미지별 토큰 박스의 평균 폭과 평균 높이를 계산한다.
3. 평균 형태에 따라 `(y, x)` 또는 `(x, y)` 정렬을 적용한다.
4. 정렬된 토큰으로 방향별 OCR 텍스트를 조합한다.
5. 기존 방식대로 평균 confidence를 계산하고 선택 방향을 정한다.

## Edge Cases

- 토큰이 없으면 빈 목록을 그대로 유지한다.
- 토큰이 하나이면 평균 형태는 계산하지만 순서는 바뀌지 않는다.
- 평균 폭과 평균 높이가 같으면 `(y, x)` 정렬을 적용한다.
- 폭이나 높이가 0인 박스도 숫자값 그대로 평균 계산에 포함한다.
- confidence 값은 방향 판단과 정렬에 사용하지 않는다.

## Testing

`tests/test_ocr_processing.py`에 다음 회귀 테스트를 먼저 추가한다.

- 평균적으로 가로로 긴 토큰들은 위에서 아래로 정렬된다.
- 평균적으로 세로로 긴 토큰들은 왼쪽에서 오른쪽으로 정렬된다.
- 평균 폭과 평균 높이가 같으면 위에서 아래로 정렬된다.
- 각 테스트는 입력 annotation 순서를 읽기 순서와 다르게 구성해 정렬 로직이
  실제로 결과를 바꾸는지 검증한다.
- 최종 방향별 텍스트와 토큰 순서를 함께 검증한다.
- 전체 테스트를 실행해 방향 선택과 디버그 confidence 표시가 유지되는지
  확인한다.

## Scope

이번 변경에는 OCR 박스 매핑, confidence 계산, 원본/회전 방향 선택 기준,
contact sheet 생성, 디버그 이미지 레이아웃 변경이 포함되지 않는다.
