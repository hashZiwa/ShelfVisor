# OCR Confidence Debug Overlay Design

## Goal

`OCR bounding boxes` 디버그 이미지에서 각 OCR 입력 이미지의 박스별
confidence를 확인할 수 있게 한다. 원본 방향과 90도 반시계 회전 방향 모두
표시 대상이며, 기존 OCR 추론·후처리·방향 선택 동작은 변경하지 않는다.

## Current Behavior

OCR contact sheet의 각 행은 원본 방향(`upright`)과 90도 반시계 회전 방향
(`rotated_ccw_90`) 이미지를 나란히 배치한다. OCR 결과는 이미지별 토큰으로
매핑되고, 토큰은 세로 좌표를 우선하고 가로 좌표를 차선으로 사용해 정렬된다.
`OCR bounding boxes` 단계에서는 두 이미지의 토큰 박스를 그리며, 평균
confidence가 높은 방향을 초록색 테두리로 강조한다.

## Display Rules

- 원본 방향과 90도 회전 방향 모두 confidence 목록을 표시한다.
- 목록은 해당 이미지 바로 아래에 작은 글씨로 배치한다.
- 한 박스당 한 줄을 사용하며 형식은 `box1: 0.95`이다.
- confidence는 소수점 둘째 자리까지 표시한다.
- `box1`, `box2` 순번은 해당 방향의 기존 토큰 정렬 순서를 그대로 따른다.
- 두 방향의 순번은 각각 `box1`부터 독립적으로 시작한다.
- 토큰이 없는 방향에는 confidence 목록이나 대체 문구를 표시하지 않는다.
- 기존 선택 방향의 초록색 강조와 토큰 bounding box 표시는 유지한다.

## Rendering Design

변경 범위는 `app/analysis/result_rendering.py`의 디버그 이미지 렌더링으로
한정한다. OCR 입력용 contact sheet나 OCR 결과 행 데이터는 수정하지 않는다.

현재 contact sheet의 행 사이 고정 여백에 텍스트를 덧그리면 토큰 수가 많을
때 다음 행과 겹칠 수 있다. 따라서 디버그용 렌더러가 각 OCR 행을 별도의
시각적 행으로 합성한다. 각 방향의 이미지 높이 아래에 그 방향의 토큰 수에
필요한 캡션 높이를 계산하고, 두 방향 중 더 큰 전체 높이에 맞춰 행 높이를
정한다. 이후 기존 3행 단위 가로 타일 배치를 유지한다.

각 방향의 캡션 시작 x 좌표는 해당 이미지의 시작 x 좌표와 맞춘다. 캡션은
이미지 바로 아래에서 시작하며, 행 내부에 필요한 여백을 포함한다. 선택
방향의 이미지 강조와 각 토큰 박스는 기존 색상과 굵기를 유지한다.

## Data Flow

1. OCR 결과를 contact sheet의 행과 두 방향에 매핑한다.
2. 각 방향의 토큰을 기존 좌표 순서로 정렬한다.
3. 기존 방식으로 이미지와 토큰 bounding box를 그린다.
4. 각 방향의 토큰 confidence를 `boxN: 0.00` 문자열로 만든다.
5. 방향별 캡션 높이를 반영해 디버그 행을 합성한다.
6. 최대 3개의 디버그 행을 한 타일로 묶어 기존 가로 스크롤 이미지를 만든다.

## Edge Cases

- OCR 행이 없으면 기존 빈 contact sheet 이미지를 그대로 반환한다.
- 한 방향에 토큰이 없으면 그 방향의 캡션 공간을 추가하지 않는다.
- 한쪽 방향에만 토큰이 많아도 다음 OCR 행과 겹치지 않도록 행 전체 높이를
  충분히 확장한다.
- 누락되거나 falsy인 confidence는 현재 후처리 규칙과 동일하게 `0.00`으로
  표시한다.

## Testing

렌더링 단위 테스트를 먼저 추가해 다음 동작을 검증한다.

- 양쪽 방향의 confidence 캡션이 렌더링 대상에 포함된다.
- 각 방향의 박스 번호가 독립적으로 `box1`부터 시작한다.
- 토큰 순서와 두 자리 소수점 형식이 유지된다.
- 토큰 수가 증가하면 캡션 영역과 결과 이미지 높이가 확장된다.
- 토큰이 없는 방향에는 캡션이 생성되지 않는다.
- 기존 전체 테스트를 실행해 OCR 매핑, 파이프라인 응답, 디버그 단계 순서가
  유지되는지 확인한다.

## Scope

이번 변경에는 confidence 기반 방향 선택 알고리즘, OCR API 호출, 최종 결과
이미지, 웹의 디버그 단계 전환 UI 변경은 포함하지 않는다.
